# 조명·월드 렌더링 방향

본 문서는 **마녀: 귀찮아** 프로젝트의 목표 장르(반 오픈월드, 지형·오브젝트 변화, 파괴, 싱글 RPG-경영)를 전제로 **조명·간접광 근사·월드 스트리밍과 맞물린 렌더링 원칙**을 고정한다. 구현 세부는 Unity 버전과 빌드 타깃에 따라 조정하되, 여기서 정한 방향을 벗어날 때는 의도적으로 재검토한다.

---

## 1. 문서 목적·적용 범위

**다루는 것**

- 라이트맵·베이크 GI·라이트 프로브(볼륨)와 **동적 라이트**의 역할 분담
- 반 오픈월드에서 **씬(청크) 단위**와 베이크 데이터의 관계
- 이동·파괴 가능 요소가 있을 때의 **태깅·전환** 원칙

**다루지 않는 것(별도 문서·작업으로 분리)**

- 캐릭터 NPR/PBR 셰이더 디테일, 헤어·의상 전용 기법
- 포스트 프로세싱 스택 전체 목록
- 오디오·물리·세이브와 무관한 주제

---

## 2. 게임 전제(요약)

| 전제 | 설명 |
|------|------|
| 반 오픈월드 | 한 번에 전부 로드하기 어려운 규모, 스트리밍·구역 로드 고려 |
| 실시간 지형·오브젝트 변화 | 지형 또는 오브젝트가 런타임에 움직이거나 형태가 바뀔 수 있음 |
| 파괴 가능 요소 | 메시가 사라지거나 조각으로 바뀌는 등 기하 변화 |
| 싱글 RPG-경영 | 탐험 외에 경영·UI 비중이 큰 구간이 있을 수 있음 |

---

## 3. 중간 결론(한 페이지 요약)

1. **정적 뼈대**(넓은 지형, 고정 구조물 등 변하지 않거나 느리게만 변하는 부분)는 **청크(씬/서브씬) 단위로 베이크**하는 것이 품질·빌드 반복 비용 측면에서 유리하다.
2. **이동·파괴 대상**은 라이트맵에 의존하기 어렵다. **동적 라이트(제한적)·그림자 예산·라이트 프로브(Adaptive Probe Volume 등)** 로 간접광을 근사한다.
3. **라이트맵만으로 전 조명을 해결하지 않는다.** 혼합(Mixed) 파이프라인이 기본 전제다.
4. **씬 분리**는 반 오픈월드에서 **로딩·메모리·베이크 단위**를 나누기 위해 자연스럽게 따라오며, Unity에서는 **씬별 라이트맵·프로브 데이터가 묶이기 쉽다**는 엔진 특성과 맞물린다(제품 사례가 아닌 파이프라인 설계 관점).

---

## 4. 라이트맵의 한계와 태깅

라이트맵은 **베이크 시점의 기하·라이트**에 묶인다. 아래는 기획·구현 시 체크리스트 수준의 가이드다.

- **정적(Static)** 으로 두어도 되는 메시만 라이트맵에 포함한다.
- **이동·회전·스케일이 런타임에 바뀌는 오브젝트**는 라이트맵 기여에서 제외하거나, 동적 조명 전용으로 태그한다.
- **파괴 가능** 오브젝트는  
  - 작은 조각: 처음부터 **프로브 + 동적**만 사용하는 편이 단순한 경우가 많다.  
  - 큰 구조물: **손상 단계 프리팹 스왑**, 또는 **파괴 직후 해당 구역만 동적 위주**로 전환하는 등 연출·예산을 문서화한다.
- 파괴·이동 시 **라이트맵 잔상**이 보이지 않도록, 셰이더/렌더러에서 **라이트맵 사용 on/off**를 상태와 연동할지 결정한다.

## 5. 권장 레이어링

| 층 | 역할 | 비고 |
|----|------|------|
| 1. 하늘·주 광원 | Directional(시간대에 따른 색·강도), Skybox/Ambient | RPG 분위기의 기준 축 |
| 2. 정적 월드 뼈대 | 청크 단위 라이트맵(또는 해당 구역 베이크) | 큰 지형·고정 건물 껍데기 |
| 3. 동적 액터 | 캐릭터·차량·움직이는 플랫폼 등 | 프로브(볼륨)로 간접색, 그림자는 예산 내 실시간/Mixed |
| 4. 파괴·변형 요소 | 파편·부서진 구조물 | 동적 + 프로브; 큰 변화는 스왑·구역 전환 검토 |
| 5. 경영·UI 중심 씬 | 상점·메뉴·실내 경영 화면 등 | 탐험과 분리 가능하면 **별 씬에서 더 공격적 베이크** 허용 |

## 6. 반 오픈월드·씬 분리

- **스트리밍 단위**(씬 또는 서브씬, Addressables 로드 단위 등)마다 **베이크를 묶으면** 수정 범위가 구역으로 한정되어 반복 베이크 비용을 줄이기 쉽다.
- **전 지형을 한 장의 씬에서 단일 대형 베이크**하면 빌드 시간·메모리·작은 수정에도 전체 재베이크가 걸리기 쉽다.
- 멀티 씬 구성 시 Unity 문서상 **라이트맵 등 베이크 데이터가 씬 단위로 로드·언로드되는 설계**와 맞추는 것이 일반적이다(정확한 옵션명·버전은 매뉴얼 참조).

## 8. 본 프로젝트와의 연결 (`PrefabLightmapData`)

[`PrefabLightmapData.cs`](../Assets/_WitchMendokusai/Content/Explorer/World/Stage/Scripts/PrefabLightmapData.cs)는 [Ayfel/PrefabLightmapping](https://github.com/Ayfel/PrefabLightmapping) 계열로, **씬에서 베이크한 라이트맵을 프리팹 인스턴스에 다시 맞추는** 용도다. 단일 씬에서 스테이지 프리팹만 바꿔 쓰는 경우 **전역 `LightmapSettings`** 와 인덱스를 수동으로 동기화하는 층이다.

**현재 구현에서 알아둘 것**

- **Non-directional 라이트맵**도 적용되도록 방향 맵이 비어 있어도 조기 종료하지 않는다.
- **`replaceSceneLightmaps`** (기본 켜짐): `LightmapSettings.lightmaps`를 **이 프리팹에 저장된 슬롯만**으로 교체해, 구역을 옮길 때마다 라이트맵 목록이 **누적되지 않게** 한다. 같은 씬에 **이 프리팹 밖**에 베이크된 지오메트리가 있으면 끈다.
- **스테이지 A/B를 끄고 켜며 재사용**할 때: `Start`는 처음 한 번만 호출되므로, **플레이 중 `OnEnable`마다 `Init()`** 을 돌려 활성화된 스테이지가 전역 라이트맵을 자기 데이터로 덮어쓴다. 파괴 후 재생성 없이도 동작한다.
- **한 프레임에 `PrefabLightmapData`가 둘 이상 켜지면** 마지막에 `Init`이 돈 쪽이 유효해진다. 전환 시 **한쪽만 활성**이 안전하다.
- 라이팅 에셋만 바꾼 뒤 순서가 어긋나면 **`RefreshLightmaps()`** 로 같은 스테이지에서 재적용할 수 있다.
